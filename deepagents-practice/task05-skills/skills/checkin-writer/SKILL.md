# checkin-writer

把一次实验记录整理成可以直接提交的打卡文档。

## 输入

用户会给：任务编号、环境、做了什么改动、跑出来什么结果。
这些信息通常散在对话里，先收集齐再动笔。

## 输出格式

正文必须依次出现这五个标题，标题文字照抄，不增不减：

1. `一、验证什么` —— 这次要回答的问题，写成问句，不要写成任务清单
2. `二、改了什么` —— 改了哪些文件、关键代码在哪一段
3. `三、实际结果` —— 只写实际跑出来的输出
4. `四、证据与解释` —— 每条结论后面跟证据来源
5. `五、下一步修正` —— 至少两条这次没做的事

## 写作规则

1. 第三段逐条贴实际输出（工具返回、日志行、断言打印），可以截断，但不能改写成评价。
2. 第四段的每条结论后面跟证据：哪一次运行的哪一条输出、哪个断言通过了。
3. 证据不足就写「未验证」，不许补数字。
4. 第五段写「这次没验证的东西」，不要写成空泛的任务清单。
5. 结尾列引用资料链接，标明课程资料的出处。

## 边界情况

- 用户没给运行输出：第三段写「本轮未提供输出」，并说明缺什么，不要推测结果。
- 材料只有概括、没有原始输出：第三段开头先写「以下为概括，未提供原始输出」，
  再逐条标出待补的证据位置，不要把概括改写成结果。
- 材料里的数字互相矛盾：两处都列出来并标注冲突，不要替用户挑一个。
